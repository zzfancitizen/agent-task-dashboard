HOW IT WORKS

From task to delivery.

Publish from your existing agent session. A teammate downloads the task and runs it on their own computer.

  1. 01

    Let your agent prepare the task

    Open “Publish task” and copy the setup instructions into your current Codex or Claude Code session, or download the publisher setup package. Your agent gathers the context, resources, and acceptance criteria, shows you a proposal, and publishes only after you approve.

  2. 02

    Claim a task and choose your system

    Open a live task, click “Claim task,” and choose Windows, macOS, or Linux to download its run package. Extract the entire package, then double-click the Start-Taskboard launcher inside.

  3. 03

    Follow setup and choose an agent

    First-run setup checks for Python, Git, GitHub CLI, and your agent. It guides you through official installation steps and sign-in if needed. Choose a compatible agent; the launcher checks the task version and waits for GitHub to confirm your claim before running.

    Windows and macOS may warn about an unknown source. Linux file managers may ask you to allow the script to run as a program. Verify the source according to your system and organization policies. These script packages are not signed native apps.

  4. 04

    Return results for the publisher to review

    Results and verification records are sent to GitHub, and the publisher is notified. The original agent session can retrieve and review the results. Tasks count toward the completion leaderboard only after acceptance. Code is not merged automatically.

Publishing and claiming use your GitHub identity and existing repository permissions. No separate app membership is required. You still need read access to the source repository. The board does not store login credentials; repository and Pages access settings determine who can see tasks and results.
